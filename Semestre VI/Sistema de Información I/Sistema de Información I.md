## Apuntes

### Descripción general y objetivos
Sistema de Información I estudia el análisis y diseño de sistemas de información en las organizaciones: ciclo de vida, levantamiento de requisitos, modelado de procesos y datos, y especificación del diseño, apoyándose en lo aprendido en [[Base de Datos I]]. Objetivo: que el estudiante analice una organización, identifique sus necesidades de información y produzca la documentación de análisis y diseño de un sistema. No hay Material del estudiante; contenido según programa típico (verificar con el programa oficial).

### Contenido programático
1. **Conceptos de sistemas de información**: datos, información, componentes, tipos (TPS, MIS, DSS, ERP), rol en la organización.
2. **Ciclo de vida de desarrollo (SDLC)**: cascada, iterativo, prototipado, ágil.
3. **Investigación preliminar y factibilidad**: técnica, económica, operativa.
4. **Determinación de requisitos**: entrevistas, cuestionarios, observación, revisión de documentos; requisitos funcionales y no funcionales.
5. **Modelado de procesos**: diagramas de flujo de datos (DFD), diccionario de datos, casos de uso (UML), diagramas de actividad.
6. **Modelado de datos**: entidad-relación, normalización, derivación al modelo relacional.
7. **Diseño**: entradas, salidas, interfaces, controles y seguridad; documentación.

### Conceptos clave
- **Requisito funcional**: qué debe hacer el sistema; **no funcional**: cómo (rendimiento, seguridad, usabilidad).
- **DFD**: procesos, almacenes, entidades externas y flujos; niveles 0, 1, 2.
- **Caso de uso**: interacción actor-sistema que produce un resultado de valor.
- **Factibilidad**: viabilidad técnica, económica y operativa.

### Ejemplo
Caso de uso "Registrar venta": Actor: cajero. Flujo: ingresa productos, el sistema calcula total, se registra la factura en la BD. DFD nivel 0: entidades Cliente y Cajero, proceso 0 "Sistema de ventas", almacenes Productos y Facturas.

### Evaluación y consejos
- Proyecto de análisis y diseño de un sistema real en equipo, con entregas y exposición; verificar ponderaciones oficiales.
- Mantén trazabilidad entre requisitos, DFD y modelo de datos.
- Valida los requisitos con el usuario antes de diseñar.
